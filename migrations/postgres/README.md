# Postgres migrations

Spec: `docs/specs/postgres-schema.md`. Applied by `ctrlz migrate` as `ctrlz_migrator`, with goose, in order.

## Layout

- `src/NNNN_name.sql` is what a person edits. It may use macros (`{{rls "table"}}`, `{{actionset ...}}`, `{{ts}}`, `{{touch "table"}}`, `{{tid}}`, `{{grant ...}}`), expanded at build time so that every table has identical text for the tenant policy and the action-and-target column set.
- `NNNN_name.sql` next to it is the expansion, committed, and embedded in the binary. `scripts/gen-migrations.sh` writes it; `scripts/gen-migrations.sh -check` and a Go test fail when the two differ.
- `bootstrap/` is not a migration. It creates the roles and the database and revokes PUBLIC, and runs once as the Postgres superuser on the local socket (the installer, or the Compose init hook). `10-cluster.sql` creates the roles and the database, `15-role-bounds.sql` sets their attributes, connection limits and role defaults (idempotent: the repair of an installed database, which `ctrlz migrate` names when a bound is lost), `20-database.sql` closes PUBLIC (idempotent as well), `vars.sh` holds the psql variables both of those files need (the initdb hook and `repair.sh` source it), `repair.sh` is the command that runs the two idempotent files on an installed database (`docker compose exec -u postgres postgres sh /ctrlz-bootstrap/repair.sh`), and `watchdog.sql` is the statement the postgres container's watchdog runs. The migrator has no CREATEROLE and could not do it.
- `../catalog/*.yaml` is the expected state of the catalog. `internal/store/catalogtest` compares the live database with it in both directions.

## Rules

- A migration that has been applied anywhere is never edited. Fix forward with a new file. Expand only in a release, contract one release later (R47). `applied.sum` is the enforcement (rule applied-migrations-are-frozen): the SHA-256 of every expanded migration, which `go run ./tools/genmig` extends for a new file and `internal/migrategen` and `genmig -check` (CI) verify. An edited, deleted or unlisted migration fails; `genmig -bump <file>` accepts an edit and is a diff a reviewer reads, to be used only for a file nothing has ever run (a fresh feature branch), never for one a database may have applied. The plain command does not start a missing or empty `applied.sum` over existing migrations either (`-init` is the explicit first listing; otherwise restore the file from version control), and it refuses an unlisted migration that sorts before the newest listed one, so deleting the manifest or one of its lines is not a bump with no flag.
- A new table needs its macro lines (`{{rls}}`, grants) and a row in `catalog/tables.yaml`, `grants.yaml` and, if it has a foreign key, `foreign_keys.yaml`. The catalog test fails until all are there, and the seed in `catalogtest/seed.go` must get a row for it.
- Grants: nothing is granted by default. `S(-a-b)` means every column except `a` and `b` at the moment the migration runs, so a column added later is not readable until a migration grants it.
- Backfills run per tenant as `SET LOCAL ROLE ctrlz_backfill`, with `set_config('ctrlz.tenant_id', ...)` for each tenant, and declare the expected total row count. Under FORCE RLS a run without the setting touches zero rows and would otherwise look like success. `TestMigratorSeesNothing` shows the pattern. Grant the backfill role its table privileges at the start of that migration and revoke them at the end.
- SECURITY DEFINER functions live in `ctrlz_fn`, pin `search_path` to `pg_catalog, pg_temp`, and are added to `catalog/functions.yaml` with an `owner`. A function that acts for the tenant of the call (`ctrlz.current_tenant_id()`) is created under `SET ROLE ctrlz_scoped`, which has no policy but `tenant_isolation` (db-r18-1); one that needs the wide policies of `ctrlz_auth` (a lookup before a tenant is known, a global table, a cross-tenant look) is created under `SET ROLE ctrlz_auth` and says why in `auth_owner_reason`. Both roles are made by `bootstrap/10-cluster.sql`.

## Deviations from the spec text

- `btree_gist` is installed in its own schema `ctrlz_ext`, not `ctrlz`: it brings about two hundred support functions, and the function checks stay exact without them.
- goose's version table is `ctrlz.schema_migrations` with goose's own columns (`version_id`, `is_applied`, `tstamp`), not `version, applied_at`.
- The two policies per outbox are named `compiler_drain_select` / `compiler_drain_delete` and `worker_drain_select` / `worker_drain_delete`, because policy names are unique per table.
- `ctrlz_auth` also gets a role-wide `ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ... FROM PUBLIC`; the schema-scoped form the spec states leaves no row and does not undo the built-in default.
- The OTP caps and the resend cooldown were constants in 0006 to 0010. Since 0011 they are columns of `system_settings` (defaults: 5 per phone, 3 per phone and network, 20 per IP, 100 per /24, 100 per IPv6 /48, 5000 global per day, 60 seconds); the OTP lifetime (5 minutes) and the five tries stay constants of the functions.
- `auth` can read `setup_share_tokens.revoked_at`, because `auth_share_by_hash` filters on it.
- `0008_review_fixes.sql` follows the design review. `ip_claim_take` needs evidence (a hub-observed, unconsumed `ip_proof_challenges` row from inside the claim), refuses a suspended claim, limits width (/32 open, /28 otherwise unless `approved_by_admin`; 0010 makes it /32 in every mode) and displaces only claims the new one covers. `ip_proof_challenges` is no longer writable by the tenant role beyond opening a challenge. OTP issue counts messages sent, keys IPv6 on the /64 and IPv4 on the host and /24, and refuses a request with no IP; OTP consume and registration are bound to a phone and purpose. `announcements` is read through `ctrlz_fn.announcements_for_tenant()`, not the table.
- `ctrlz_migrator` is not a boundary against its own secret: it owns the tables and can undo FORCE RLS or `SET ROLE ctrlz_auth` or `ctrlz_scoped`. It logs in only from the address of the migrate container (`deploy/compose/postgres/pg_hba.conf`), and `TestMigratorSeesNothing` shows only that a plain SELECT returns nothing.
- `0009_proof_and_claims.sql` is the second review round. `ip_proof_challenges` gets `observed_protocol` (udp, tcp, dot, doh, doq), `attempts`, and CHECKs: the observation columns come together, a `udp` observation has a `txt_code_hash` (32 bytes), and `expires_at` is at most 15 minutes after `created_at`. The tenant has no INSERT or UPDATE on the table and reads it without `txt_code_hash` and `observed_ip`; `ctrlz_fn.ip_claim_open_challenge(claim)` makes the label (26 characters of `[a-z2-7]`) and the 10 minute expiry. The hub writes `observed_at`, `observed_ip`, `observed_protocol` and `txt_code_hash` (the SHA-256 of the TXT code it derived from `proof_key`, which is never in Postgres). `ip_claim_take` decides from the evidence: a TCP-class observation is enough, a `udp` one needs the code, a wrong code adds to `attempts` and the fifth consumes the challenge, and `proof_method` comes from the evidence (0010 removed the method argument, and with it the `browser_ip` exception). A victim is displaced only if the new claim covers it and it contains the observed address. An active claim with `proven_at` NULL takes fresh evidence and is then `already_active`; an unproven claim, grace included, is still replaced at once by another tenant's fresh proof (the Plan's rule). A suspended claim cannot be released or requested again by its tenant. `ip_claim_request` refuses 0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.168/16, 224/4 and 240/4 (and any prefix that overlaps them) with `invalid_address`; the documentation ranges stay accepted because they never occur as a real source and the fixtures use them.
- OTP issue also keeps at most 3 messages a day per (phone, source network) (`sms_counters.scope = 'phone_net'`) and one message per (phone, purpose) per 60 seconds, both counted on messages sent. The numbers are provisional (D31).
- The tenant role cannot write `users.phone_e164` or `phone_verified_at`; a SECURITY DEFINER phone-change function arrives in P1. `endpoints.admin_hold` stays readable by the tenant (it must see why an Endpoint is off) and unwritable.
- `nodes.resolve_mode` is `recursive`, `upstream` or `hybrid`. `clients` and `schedule_windows` refuse Profile 2 without Profile 1 or equal to it. `block_pages` limits the title (120 characters), the message (2000) and the unblock link (https, a host, no user part, 2048). The rule that a multi-mode filter needs a mode is deferred to the P2 write path.
- `0010_gate_fixes.sql` follows the P0 gate review. `ip_claim_take(claim, code, batch_id)` has no method argument: `proof_method` is `verify_tcp`, `verify_udp_txt` or `secure_dns`, from the evidence, and `browser_ip` is gone from the CHECK (how an address was supplied is `ip_claims.source`). It takes the batch id of the caller's transaction (NULL gets `invalid_batch`) and writes one `endpoint_set` `policy_outbox` row for each tenant it displaced and for the taker, in the subtransaction of the displacement, so the delete and the put are one config entry; `ctrlz_auth` has INSERT on `policy_outbox` through the policy `auth_endpoint_set`. A claim wider than /32 is never proven without `approved_by_admin`, in every mode. Take locks the tenant's overlapping claims in id order and refuses while another of them is suspended; `ip_claim_open_challenge` does the same refusal and allows 10 live challenges per claim; `ip_claim_request` locks the overlapping claims before it looks for a suspended one and copies `first_grace_at` from the maximum `first_grace_at` of the tenant's overlapping claims. It takes a per-tenant advisory lock first and refuses with `quota_exceeded` when the tenant already holds `max_ip_claims` claims that are not released (a new column of `entitlement_defaults`, default 50, and an override in `tenant_entitlements`; `ctrlz_auth` reads only that column, through the policy `auth_limits`). `endpoints` has one RESTRICTIVE policy, `hold_blocks_delete`, `FOR DELETE TO ctrlz_tenant`: an Endpoint with `admin_hold` or a suspended claim is not deleted by the tenant (zero rows, no error), while the worker's tenant purge cascades as before. A suspension that has not committed is invisible to the policy, so a `BEFORE DELETE` trigger on `ip_claims` (`suspended_claim_stays`) raises SQLSTATE `CZ001` when it is asked to delete a suspended claim whose tenant still exists; the store maps it to `ErrConflict`. `auth_otp_issue` checks the 60 second cooldown after the counters, so overlapping calls for one phone send one message: the row lock of the global counter (which every call that will send a message takes, last of its keys) serialises the sends, and a decoy, which has no global key, is ordered by the phone's own row. `auth_totp_seed` compares its tenant argument with the setting when there is one. The worker can select the key and expiry columns of `ip_proof_challenges`, `setup_share_tokens` and `profile_download_tokens` (sweeps), and the hub `last_seen_at` of `ip_claims`, `clients` and `authorized_ips` (to keep the maximum). `block_pages` needs `unblock_mode = 'custom'` exactly when there is a link, and the link is ASCII with a plain host (`wire.ValidateBlockPage` is the authority, the table a backstop); its title and message hold no control character. `catalog_filter` native ids are below 1000 and third-party ids start there; `catalog_service.wire_id` is a bigint up to u32. `tenant_profile_counts.option_count` does not count `default_location_unavailable`. A `BEFORE DELETE` trigger on `profiles` (`promote_profile2`) moves Profile 2 up when a client's Profile 1 is deleted, if the Profile 2 row still exists; it locks the clients first (`FOR NO KEY UPDATE`, in id order: a statement that locks several clients of a tenant locks them in id order, and the P4 hub batch and any P3 bulk write are bound by it; the rule does not make a writer safe against a delete, 40P01 is `ErrRetry` and the store retries for nobody, so a route that deletes an Endpoint or a profile locks the affected clients first and retries, and every writer bound by the rule retries too; see the comment in 0010), so a concurrent change of a client's Profile 2 is seen, and it writes no outbox row, so a route that deletes a profile also marks the tenant's `endpoint_set`. `ip_claim_open_challenge` takes the tenant's advisory lock of `ip_claim_request` first and refuses once the tenant has ten times the larger of its `max_ip_claims` and the claims it holds live challenges; it can wait through that lock behind another tenant's take that holds one of its claim rows, bounded by `lock_timeout` (accepted, see the comment in 0010). The bracket form of the `block_pages` link check is looser than the validator (`https://[1:2]/` passes the table and not `wire.ValidateBlockPage`); the compiler runs the validator on each row. `roles.yaml` now pins connection limits and role defaults (test profile values), `policies.yaml` marks restrictive policies, `functions.yaml` lists the delete-guard triggers, and `genmig -check` fails on a `0*.sql` that has no source.
- `0011_auth.sql` is P1 (spec `docs/specs/p1-auth.md` section 16). Six global tables (`auth_tickets`, `auth_throttle`, `admin_jobs`, `sms_outbox`, `sms_deliveries`, `sms_provider_templates`), new columns on `sessions`, `users`, `webauthn_credentials`, `otp_challenges`, `invites`, `sms_gateways`, `system_settings`, `admin_users`, `admin_sessions` and `audit_log`, and the grants the sweeps and the admin need. `ctrlz_tenant` loses UPDATE on `phone_change_requests`: only `auth_phone_change_complete` finishes a request. `ctrlz_fn` gets USAGE for `ctrlz_admin`, which held EXECUTE on `admin_create_user`, `admin_throttle_hit`, `admin_throttle_reset` and `auth_tickets_revoke` only (0012 and 0014 added `admin_reissue_one_time_password` and `admin_one_time_state`; the live list is `catalog/functions.yaml`). `auth_otp_issue` has a sixth argument (`p_trusted`) and the old five-argument form is gone; a decoy (no `delivery_ct`) counts on every key but `global`, and from `otp_soft_pct` of the global cap on a device we do not know is refused. `auth_session_by_hash`, `auth_passkey_by_credential` and `auth_user_by_phone` return more columns and were dropped and created again, so their grants were repeated. `auth_user_by_phone` ends with `password_changed_at` (and `ctrlz_auth` may select that column), which the login compares under the user row lock (P1 auth review round 1, db-r1-1; 0011 was edited because it has not been applied anywhere). T-536 (D46): the CHECK `users_one_time_password` makes `password_expires_at` mean an admin-issued one-time password, `ctrlz_admin` could update `password_expires_at` (0012 took that away) and reads the key columns of `refresh_tokens`, and `auth_tickets_revoke` is open to it. One deviation from the spec text: the worker holds INSERT only on `alerts` and cannot look for an earlier alert, so "once an hour per gateway" is "one open alert per kind and key": the partial unique index `alerts_open_key_uq` and `INSERT ... ON CONFLICT DO NOTHING` do it, and an operator's ack lets the next failure alert again.
- `0012_admin_reissue.sql` follows the P1 auth review round 1 (finding admin-r1-17). `ctrlz_fn.admin_reissue_one_time_password(user, hash)` decides whether a user may have their one-time password replaced (the password is still an admin-issued one, no second factor, the tenant is not being deleted) and does the update under the row lock, as `ctrlz_auth`, on the tenant of the transaction setting. `ctrlz_admin` loses UPDATE on `users.password_hash`, `must_reset` and `password_expires_at`; `ctrlz_auth` gets them. The rule of spec 10.7 therefore holds for any code running as `ctrlz_admin`, not only for the Go handler.
- `0013_admin_narrow_credentials.sql` follows the P1 auth review round 2 (findings db-r2-1 and db-r2-5). `ctrlz_admin` loses the table-level UPDATE that 0007 gave it on `sessions`, `refresh_tokens`, `api_tokens` and `webauthn_credentials` and keeps `UPDATE (revoked_at)` on the first two (the admin code only revokes). A token hash is a plain SHA-256, so UPDATE on `token_hash` (or `public_key`, `credential_id`, the expiries) was a way to take over any user of any tenant for code running as `ctrlz_admin`, the same reach 0012 closed for `password_hash`. `catalogtest.TestAdminCannotRewriteCredentialsOrTokens` asks `has_column_privilege` for every column of the four tables.
- `0014_admin_totp_declare_lost.sql` follows the P1 auth review round 2 (finding admin-r2-5). `ctrlz_admin` loses its last UPDATE grant on `users` (`totp_secret_ct`, `totp_enabled_at`, `totp_last_step`, `enforce_passkey`): code running as it could otherwise switch off any tenant's user's second factor. `ctrlz_fn.admin_one_time_state(user)` is the lock-and-read of the one-time password re-issue (a row lock needs UPDATE on some column), taken as `ctrlz_auth`. `declare-lost user_totp` now calls `ctrlz_fn.admin_totp_declare_lost()`, which can only set the three TOTP columns to NULL, for the tenant of the transaction setting and for users that have TOTP enabled; `ctrlz_auth` gets UPDATE on those three columns for it. `catalogtest.TestAdminCannotRewriteCredentialsOrTokens` also asks every `users` column.
- `0015_admin_no_silent_second_factor.sql` follows the P1 auth review round 3 (findings db-r3-1, db-r3-5 and db-r3-6). `ctrlz_fn.admin_totp_declare_lost()` is dropped: a function the admin role could execute only moved the attack on a user's second factor from an UPDATE to a call, because the tenant setting is a GUC any session can set. Its replacement, `ctrlz_fn.worker_totp_declare_lost(p_key_number)`, is EXECUTE-granted to `ctrlz_worker` only (the tools container's `ctrlz declare-lost user_totp`, which holds the `user_totp` key ring and refuses while the key is still in it). It clears only seeds whose header (bytes 3 and 4 of the ciphertext) names the key, and writes the tenant's `totp_lost` notice and a `tenant_audit_log` row (`totp.declared_lost`) in the same call, so `ctrlz_auth` gets INSERT on those two tables. `ctrlz.revocation_stays()` is a `BEFORE UPDATE OF revoked_at` trigger on `sessions`, `refresh_tokens` and `api_tokens`: once `revoked_at` is set no statement changes it (SQLSTATE 42501), so the column grant `ctrlz_admin` keeps for revoking cannot be used to bring back a stolen cookie. `catalogtest.TestDeclareLostRunsAsWorker`, `TestAdminCannotSwitchOffASecondFactor` and `TestRevocationIsOneWay` show it; the mutation tests switch the triggers off.
- `0016_admin_outbox_columns.sql` follows the P1 auth review round 4 (finding sms-r4-7). `ctrlz_admin` held table-level INSERT on `sms_outbox`; the worker applies the daily outbox cap on a message's first claim, which it recognises by `attempts = 1` after the claim, so a row inserted with `attempts` already above 0 was sent without ever being counted. The grant is now `INSERT (id, kind, gateway_id, phone_e164, template_key, locale, params_ct, created_by)`, the columns of `store.qSMSOutboxInsert`; `attempts`, `state`, `claimed_until`, `last_error`, `created_at` and `sent_at` take their defaults. `catalogtest.TestAdminCannotPresetTheOutboxBookkeeping` shows it.
- `0017_worker_reach.sql` follows the P1 auth review round 4 (findings db-r4-1, db-r4-3 to db-r4-9). **It needs a new login role, `ctrlz_keytool`, which only `bootstrap/10-cluster.sql` can create**: a database whose bootstrap predates this file fails the migration with a message saying which lines to run as the superuser (`CREATE ROLE` and `ALTER ROLE ... SET` for the role, `GRANT CONNECT` from `20-database.sql`), and the installer must also add the `pg_keytool_password` secret (`scripts/gen-secrets.sh`), the `pg_hba.conf` line for 10.213.77.201 and `CTRLZ_PG_CONN_KEYTOOL`. The long-running worker reads login codes (it holds `otp_delivery`), so nothing that can rewrite or switch off a second factor, or erase the notice and audit row of a switch-off, may be reachable with its password. The one-shot `rekey` container (`user_totp` rekey and declare-lost) is now `ctrlz_keytool`, with `SELECT (tenant_id, id, totp_secret_ct)` and `UPDATE (totp_secret_ct)` on `users`, `SELECT (id)` on `tenants` and `EXECUTE` on `ctrlz_fn.keytool_totp_declare_lost` (which replaces `worker_totp_declare_lost`). `ctrlz_worker` loses `SELECT (totp_secret_ct, enforce_passkey)` and `UPDATE (enforce_passkey)` on `users`, every grant on `webauthn_credentials`, `auth_tickets` and `auth_throttle`, and `DELETE` on `notifications`; its `DELETE` on `tenant_audit_log` is bounded by the restrictive policy `worker_retention` (365 days). Its remaining jobs are functions: `worker_passkeys_mark_stale(rp_id)` and `worker_enforce_clear_without_live(rp_id)` act only for the RP ID in `webauthn_config` and the second leaves a notice and an audit row, `worker_sweep_throttle(limit)` and `worker_sweep_tickets(limit)` delete what the sweeps always deleted. `ctrlz_admin` loses `SELECT` on `sms_counters` (raw numbers and networks) and reads `admin_sms_stats(days)`, the global rows only. `admin_one_time_state` and `admin_reissue_one_time_password` lock the user with `FOR NO KEY UPDATE`, as `store.qUserLock` does, because `FOR UPDATE` conflicts with the `FOR KEY SHARE` of every insert into `sessions` or `refresh_tokens` and formed a deadlock cycle with Refresh. `catalogtest/review_r4_db_test.go` shows each.
- `0020_role_reach.sql` follows the P1 auth review round 5 (rule role-reach, `catalog/guarded.yaml`, catalog checks 22 and 23). The worker loses `UPDATE (totp_secret_ct, totp_pending_at)` and `SELECT (totp_enabled_at, totp_pending_at)` on `users` (`ctrlz_fn.worker_sweep_pending_totp()`) and `DELETE` on `sms_deliveries` (`worker_sweep_sms_deliveries(limit)`); the key tool loses `UPDATE (totp_secret_ct)` (`keytool_totp_replace(user, old, new)`, a compare-and-swap that refuses NULL); the admin loses `UPDATE (revoked_at)` on `sessions` and `refresh_tokens` (`admin_revoke_user_sessions(user)`) and keeps on `invites` only the columns its three statements use. `ctrlz_auth` gets the columns those functions need. `testdata/ctrlz_<role>_grants.golden` now exists for every role and lists table and column privileges, schema USAGE, EXECUTE on every function and the policies that apply.
- `0021_clock_source.sql` follows the P1 auth review round 5 (rule clock-source, `catalog/clocks.yaml`, catalog check 24). Every security timestamp column has one clock. `users.password_expires_at` is a database-clock column, so `auth_user_by_phone` gains `password_expired` (computed on the database clock, in a statement of its own because the row also carries the application-clock `enforce_lift_at`) and Go stops comparing the expiry; `invites.expires_at` is a database-clock column (compared inside `auth_register_user`), so `auth_invite_by_hash` gains `expired` and the invite and the phone-change request are stamped by the database from a lifetime. `sessions.last_seen_at`, `admin_sessions.created_at` and `audit_log.at` are application-clock columns and lose `DEFAULT now()`: an insert that forgets them fails instead of using the other clock. The catalog check also forbids a definer function that takes a timestamp, requires a mapping in `clocks.yaml` for every timestamp a definer function returns, and judges the live bodies of the functions with the same reader as the Go lint (`internal/clockrule`).
- `0022_credential_gen.sql` follows the P1 auth review round 5 (rule credential-generation, `catalog/guarded.yaml` `credential_gen`, catalog check 25). `users` and `admin_users` carry `credential_gen`, a counter that `ctrlz.credential_gen_bump` (one trigger function, the watched columns are the trigger's arguments) moves whenever a credential column changes, whoever writes. An mfa ticket stores the generation it was made under (`auth_tickets.subject_gen`; a ticket without one never holds), and `auth_user_by_phone` and the ticket functions return it. Every artefact derived from a first-factor check is refused when the generation or the subject of the locked row differs (`internal/credgen`).
- `0023_caps.sql` follows the P1 auth review round 5 (rule caps-and-endings, `internal/caps`, catalog check 26). Every cap is compared with one expression, `ctrlz.cap_reached(spent, cap)` (`cap IS NOT NULL AND COALESCE(spent, 0) >= cap`), executable by `ctrlz_auth`, `ctrlz_tenant` and `ctrlz_worker` and listed under `helpers` in `functions.yaml` with its `execute` roles. `auth_otp_issue` is replaced with the body of 0011 and three comparisons changed to the helper (the per-key upsert, the global and money pre-check, the soft threshold); its behaviour is unchanged. The worker's outbox gates (`OutboxFirstGate`, `OutboxRetryGate`) and `Tx.PasskeyAdd` call the same helper. Check 26 fails for a column named `*_cap*` that no entry of `internal/caps` names and for any function that orders a `*_cap*` value another way.

- `0024_credential_state.sql` follows the P1 auth review round 5 (rule one-time-state, `internal/auth/credstate`, `internal/lint` `TestOneTimeStateRule`). `ctrlz.credential_state(one_time, expires_at, needs_second_factor)` is the one function that turns must_reset or must_change_password, password_expires_at and the missing second factor into `one_time_live`, `one_time_expired`, `chosen_no_second_factor` or `ready`, on the database clock (a one-time password with no expiry reads as expired); `ctrlz.one_time_expiry` shows its end in the admin Users list. `auth_user_by_phone`, `auth_session_by_hash` and `admin_one_time_state` return the word instead of the columns (`restricted` leaves the session lookup: the gate of a request asks the table with the state the user has now). Every change of the state is a definer function that checks the edge: `tenant_set_password`, `admin_reissue_one_time_password` (now over the state), `admin_account_bootstrap`, `admin_account_reset` (with or without the authenticator), `admin_account_set_password` and `admin_account_totp_enable`. `ctrlz_tenant` loses UPDATE on `users.must_reset`, `password_expires_at` and `password_changed_at`; `ctrlz_admin` loses INSERT on `admin_users` and UPDATE on `must_change_password`, `password_expires_at`, `password_changed_at` and `totp_enabled_at`; `ctrlz_auth` gets the columns the functions need. `admin_users.password_expires_at` moves to the database clock, and `password_changed_at` and `totp_enabled_at` become records (a definer function cannot take a timestamp). The lifetimes (72 hours, 24 hours, an hour) are in the function bodies; `TestCredentialStateEdges` pins them to `password.UserOneTimeLife` and `AdminOneTimeLife`. The edges are `credstate.Edges`, and `TestCredentialStateEdges` and `TestUserCredentialStateEdges` run every function from every state.
- `0025_bounded_sweeps.sql` follows the P1 auth review round 5 (rule bounded-sweeps, `internal/sweepbatch`, `internal/lint` `TestBoundedSweeps`). `ctrlz_fn.worker_sweep_pending_totp` takes `p_limit` and clears at most that many abandoned TOTP setups of the tenant of the transaction (a bounded batch by primary key, the same 15 minute predicate repeated in the outer statement); the sweeper calls it in its own transaction, like every other batch.
